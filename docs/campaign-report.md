# 繰り返しプレイの難易度検証レポート（フェーズ7c）

- 生成: `npm run campaign-report`（各200キャンペーン、1キャンペーンは最大40プレイ）
- ゲームの仕様・数値は変更していない（各案はシミュレーター上の比較）。ボットは `src/core/analysis/campaign.ts`
- 目標（SPEC 5.7）：ストックなしの初回プレイは**10〜30戦程度**で終了し、**10〜20回目くらいのプレイで初完走**

## ボットの動き

- **1回のプレイ**：`simulateRun`（run.ts と同じ結果になることをテスト済み。ストックから連れて行った選手の制限も同じ）
- **作戦**：最適化した作戦（`optimizedPlan`）。比較用に「敵AIと同じ作戦」（不慣れなプレイヤーの想定）も測る
- **補強**：選手優先（ライフ1のときだけライフを買い、あとは相手の最強選手を獲得。ストックの選手は売らない）。比較用にバランス・ライフ優先も測る
- **ボス報酬**：ストック以外で総合力の最も高い選手。**通常戦の敗北・引き分け**：次戦に進む。**ボス戦**：勝つまで再戦
- **ストック**：ゲーム終了時に保有選手を全員ストックへ（上限200人。超えたら総合力の低い順に外す）。ニューゲームでは総合力の上位3人を連れて行く

## まとめ

1. **現仕様**：初完走までのプレイ回数の中央値は23回（20回以内に完走41%）で目標（10〜20回）よりやや遅く、**初回プレイが中央値5戦で短すぎる**（目標10〜30戦）。初回プレイでは、同じ強さの相手（500同士）に4割ほど負けるうえ、10戦目のボス（650）がほぼ越えられないため。
2. **初回を長くする調整（初期ライフ・敵の初期強さ）だけでは、完走が早くなりすぎる**（初期ライフ5で中央値12回、敵の初期強さ450で9回）。先に進めるほど強い相手から選手を獲得でき、ストックが速く育つため。
3. **「序盤をやさしく、上昇幅を大きく」**すると、両方の目標を満たせる。**案A**（通常400・ボス500・上昇+75）と**案B**（通常400・ボス525・上昇+80・初期ライフ4）は、初回プレイの中央値11〜12戦、初完走の中央値14回（20回以内に85〜87%）。案Cは初回プレイがやや短い（中央値9戦）。
4. **方針による差**：「バランス」方針でも結果はほぼ同じ。作戦を敵AIと同じにした「不慣れなプレイヤー」の想定でも初完走は12回前後で、作戦の上手下手の影響は小さい（docs/balance-report.md と同じ傾向）。
5. **「ライフ優先」（ポイントをすべてライフに使い、選手を獲得しない）では、どの案でも40回以内に完走できない**。チームが強くならないため。補強が進行の要であることをプレイヤーに伝える工夫（説明・ヒント）があるとよい。

### 注意点
- 案A・Bでは終盤の相手が強くなる（100戦目のボスは案A 1175・案B 1245）。試合エンジンのバランスは平均総合力500〜1100で確認済みで、それより上（両チームとも能力の上限に近い）ではやや打高になる傾向がある。採用する場合は `npm run balance` で1200前後も確認する。
- ストックの上位3人は10回目のプレイで総合力1250〜1350、20回目には上限（1500）に近づく。上限に達した後は「残り9人をどう強くするか」が勝負になる。
- ボットのストックの残し方は「総合力の高い順に上限まで」。実際のプレイヤーは好みで残すため、もう少し遅くなる可能性がある。
